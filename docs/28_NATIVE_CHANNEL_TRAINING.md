# Native channel training sessions

## Customer behavior

Training Studio selects an existing agent and one of its assigned channels. No trainer identity, special profile, or WhatsApp number selection is needed. Turning training on creates one tenant-scoped session for the whole channel. AI replies and automated follow-ups are suppressed while the session is open; separate HUMAN and PAUSED conversation handoffs remain intact. Turning training off immediately resumes AI with the existing published prompt and starts synthesis from the cumulative approved examples for that agent, including earlier retained sessions. A successful validated update is published automatically. An empty session makes no prompt change. If the update fails, AI continues with the previous prompt and the failed session can be retried. Optional manual examples and candidate review remain a separate workflow.

Only customer inbound messages and successfully delivered HUMAN replies sent through Customer Panel, or eligible replies observed from the provider's original business inbox, can form session examples. Both sides of a pair must belong to the same conversation and the same ON interval. A queued, failed, AI-generated, or other app/API reply is not a training demonstration. Provider event time, rather than webhook arrival time, determines the boundary for native events. Because Meta timestamps have millisecond precision and server session boundaries have finer precision, native messages in the ambiguous ON/OFF boundary millisecond are excluded. Text and media captions can form training examples; uncaptioned media is not converted into a text demonstration.

The Page Inbox app ID identifies the sending app, not the person who typed a reply. Meta also offers [automated Instant Reply inside Business Suite Inbox](https://www.facebook.com/help/1698046970464236/); the available webhook documentation does not establish a human-versus-Inbox-automation flag. Disable Inbox automations during training and review captured examples **before turning training off**, because OFF publishes a successful update automatically. A live test on the selected Page must verify actual echo payloads and automation behavior before claiming human-only attribution.

The application database owns the session and captured message records. The 20-message operational conversation cache is not the training dataset. Provider message IDs deduplicate callbacks. Synthesis uses a snapshot of approved examples and session events. If a delayed event or review change alters the dataset during the update, publication fails as stale and the failed session can be retried. A delayed historical event arriving after a successful publication cannot change the published prompt retroactively; its approved example is included in a later session update. Tenant data export includes sessions, captured events, examples, and synthesis jobs. The configured training retention policy can expire older examples and sessions.

## Customer API

- `GET /v1/tenants/:tenantId/agents/:agentId/training-sessions?channelAccountId=:channelId` returns scoped session history, captured/example counts, update status/error, and the channel's training capability reason and eligible reply source.
- `POST /v1/tenants/:tenantId/agents/:agentId/training-sessions` with `{ "channelAccountId": "..." }` verifies the assigned, connected channel and at least Customer Panel reply capability, then turns training on. Native echo eligibility is evaluated separately; unverified native echoes are excluded.
- `POST /v1/tenants/:tenantId/agents/:agentId/training-sessions/:sessionId/stop` turns training off and queues automatic synthesis and publication when the session produced approved examples. It returns no job for an empty session. Repeating the request is safe.
- `POST /v1/tenants/:tenantId/agents/:agentId/training-sessions/:sessionId/retry` retries a failed update after its cause is fixed, using a fresh dataset snapshot.

The mutating endpoints require a tenant/business-scoped owner, admin, or staff session plus CSRF validation. A single open session is allowed per channel, and an update in progress blocks overlapping ON/retry work. Agent reassignment, channel disablement or credential changes, and agent/business archival are blocked during an open session. The session status and provider capability are read-only to the Training Studio; no trainer identity is requested.

Those tests stubbed Meta's Page subscription response. A Page must not be shown as native-echo capable based on synthetic fixtures alone; its live subscription is checked when native eligibility is evaluated. Customer Panel reply training does not depend on that subscription.

## Verification matrix

For each channel, send an authorized customer message and successful Customer Panel HUMAN reply during Training ON, then verify the pair is captured only after provider acceptance. Test failed/queued Panel sends and AI/API app outbounds as exclusions. On a test-safe Facebook Page, also compare replies from the original Page Inbox and other connected API apps. Record each webhook's account, contact, message ID, provider timestamp, source field, and signature validation outcome. Confirm eligible replies pair with the correct customer. Test automated native greetings separately: a native app marker by itself may not distinguish a person from a platform-generated greeting.

Test session boundary and state separately: pre-ON, during-ON, post-OFF, duplicate and delayed callbacks; queued AI and follow-up jobs; independent HUMAN/PAUSED handoffs; immediate AI resumption with the previous prompt; successful automatic publication; a second session reusing earlier examples; an empty session; failed synthesis and retry; late-event stale-publication rejection; and cross-tenant/channel authorization. Report any provider test that cannot be run as **SKIPPED**, with the missing prerequisite.
